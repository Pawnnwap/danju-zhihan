# 03 · 验证计划（90 天真实场景试点）

## 1. 验证目标

回答四个问题：真实用户会不会用？建议有没有被执行？执行后有没有减少损失/降低成本？方案能不能复制到下一个产区？

**能力边界先说清**：本轮 90 天能回答前两问；第三问只能回答"有没有出现可记录的执行动作"，回答不了"减损多少"（需跨年多事件）；第四问**本轮不做验证**（12 个月内只做丹江口一地，复制性证据等级=0，见 §5、§6）。

## 2. 目标用户、招募与预算上限

- **对象**：丹江口库区 1–2 家柑橘合作社（或种植大户 + 乡镇农技员），覆盖 30–100 亩果园；
- **招募方式**：通过库区乡镇农技服务中心、合作社对接；已准备口头/文字版需求访谈提纲；
- **线下执行（本项目最大的单点风险，直说）**：团队常驻杭州。安排为**现场两次**（第 1–2 周启动与基线访谈、第 11–13 周期末复盘），中间 8 周以微信回访维持；现场成行受阻则整体降级为 §7 的访谈式试用并按 §3 小样本口径报数。

**试点现金预算（全部由项目人自担，无任何外部资金，也未列入任何申报预算）**：

| 项 | 上限 | 说明 |
|---|---|---|
| 现场差旅（2 次往返 + 各 2 晚住宿） | ≤2000 元 | **未询价**，按杭州↔丹江口公开票价量级估列；实际以询价为准，超支按下方砍序处理 |
| 确认回路误工补偿 | 600–1200 元 | 计价标准 100–150 元/人日 × 6–8 人日；**付款对象默认对公**（见 §3） |
| 试点期大模型用量（DeepSeek Key） | ≤100 元 | 由项目方统一提供，超量即停用该分组 |
| 打印、张贴材料与访谈小礼品 | ≤100 元 | 末端传达核查所需 |
| **合计上限** | **3200 元** | 现金总上限，写死在此 |

**超支砍序（先砍什么，事先定死不临场决定）**：①现场两次 → 一次（期末复盘改电话）；②取消"周报代运营"分组；③取消大模型/规则分组对比（全部走规则问答，省 100 元与协调成本）；④最后才压缩访谈样本量。**不会用"减少记录项"或"降低判据"来省线**。

- **试点前置协议（未签则不启动）**：**先定性**——这是**试点内部安排**，不是项目层面的责任架构：在线 Demo 对全世界开放、任何人可自部署，未签协议的访问者与末端农户不在其覆盖范围内，页面与导出报告的普遍免责句才是对他们生效的那一层。另需核验：乡镇农技服务中心（事业单位）是否有权替个人开发者签署免除或限制侵权责任的条款（外部事实，**待核验后回填**，未核前不假定协议具有法律效力）。协议至少含六条：①工具仅为农事辅助、不构成灾害预警；②错误提示的责任上限与免责范围；③数据用途、留存期限与撤回方式；④署名与成果发布须经书面同意；⑤试点失败或退出时撤销背书的表述口径；⑥**试点期全部免费，不构成任何延续性服务或价格承诺**（防止"先免费再收费"被视为既有承诺，也避免污染后续支付意愿询价）。**WTP 询价流程**：先以书面方式给出报价与包含内容，再问支付意愿；不在同一场访谈里既送服务又问意愿。在此之前，材料不声称已获任何单位同意。**"没有任何单位签字"本身按证据处理**：它构成"基层不愿为未验证工具背书"的需求信号之一，将写入复盘结论，而不是仅当作执行障碍绕过。
- **伦理与证据留存**：不采集个人身份信息（姓名、手机号、门牌）；使用数据仅含园块坐标与反馈评分。凭证处理：入库前对群名/昵称/头像打码；抽核问答只记编号与答案不记姓名；原始凭证仅本地留存、不随仓库开源，对外证据包只用**聚合统计**且经书面同意；参与者退出即删原始凭证、仅保留匿名聚合值。

## 3. 验证设计（90 天，三段）

### 第 1–2 周：基线与校准
- 访谈记录：当前如何决策灌溉/防冻/花期管理（原话留存）；
- **确认回路的实际工作量（先算账，不谈理想）**：按 `docs/02` §4 的十年基线与现行建议库条目数折算——越冬窗口（约 11/25–2/28）单园块"中/重"级冻害日中位约 2 天、"轻"级及以上约 8–15 天，`freeze.dormant` 每提示日并发动作 4 条（其中 2 条属需确认的外部性动作），1–2 家试点户计，整个试点季需人工确认的**条目·日**组合约 **16–120 次**；按每条 2–3 分钟计，即 **0.5–6 小时**，落在 §3 列支的 6–8 人日预算内，且实际发生量取决于今冬寒潮次数（暖冬年份可低至十余次）。超出部分的兜底顺序：①同一条动作在同一物候期内**只确认一次**（季度批量预确认，审规则库而非逐条）；②未确认项一律留在"待当地确认清单"，不进入可执行建议（产品侧 fail-closed，见 `docs/02` §7.3），**不会因为确认不及时而自动放行**；③若整季确认响应为零，即触发 §8 的工作台形态评估。**露天焚烧与农膜残留的答复权限通常不在农技员而在乡镇政府/生态环境部门**（具体条例待核验后回填），因此这两类动作在核清权限前一律不升格。
- 用试点园块坐标替换默认坐标；按当地品种微调物候表起止日期；
- 对照方式：试点户决策记录 vs 邻近未使用户的常规决策（"邻近未使用户"存在自选择偏差，对照仅作参考，不做因果宣称）；
- **投入品与生态外部性确认回路**（水源区特化）：分级标准不是"化学/非化学"，而是**是否有环境外部性**——①先确认才推送（fail-closed）：化学品类（磷酸二氢钾、保水剂、防冻保护剂）、农事熏烟与明火、地膜/防寒布等覆盖材料（残膜与废弃物去向）、大水漫灌类灌溉动作；②可自动推送但标注"未经农技员确认"：覆盖秸秆、涂白、培土、遮阳、修剪等非外部性动作；③常规动作按季度批量预确认（审规则库而非逐条建议）。规则库增设"库周限用/禁用投入品与禁烧/覆膜规定"核对项（当前为盲区，已列入试点任务）。**农技员能否就焚烧管控与农膜残留作答，本身属待核事项**（基层农技员通常不握有焚烧审批口径），核不出答案前该两类动作一律不推送。
- **确认回路的激励与付款合规（前置核验，未核清前不成立）**：误工补偿**默认以单位对公方式支付**（支付给合作社或乡镇农技服务中心，由其内部按规定分配），不默认向在编人员个人付现金——乡镇农技推广人员多属财政补助事业单位在编，个人兼职取酬受相关规定约束（**具体条款待逐字核验后回填**）。核验三问：①哪种身份可收；②以谁的名义支付、谁代扣个税；③若个人不可收，这笔钱改付给谁（合作社管理员/聘用对接人/单位购买服务）。任一问答不出，即取消现金激励、直接走 §8 的"工作台"收窄分支——**这一条是本项目核心机制的前提，不是细节**。非现金激励照旧：系统代生成风险周报替其省工、试点成果署名归其单位。基层农技推广考核中没有"配合外部工具逐条确认"这一项，因此不假设义务劳动可持续。

### 第 3–10 周：真实使用（覆盖一个完整风险过程）
- 每周回访一次（微信），记录：①**提示接收**（本周收到哪些中/重级提示）；②**动作采纳**（执行了什么、未执行的原因）；③**主观评价**（1–5 分 + 是否愿继续用 + 是否愿推荐）；④**提示负担**（本周页面打开次数、查看的"轻"级及以上提示条数——**不含"关注"**、有无主动要求"少提示"）；⑤**墒情观测**（每周一次 10cm 土层手捏墒情三档：干/润/湿，加上本周实际灌水日期与灌量估计）。
- ④必须与周活跃**同时**报出：本工具无推送通道（无账号、不落库），"没人抱怨"分不清是"负担合适"还是"根本没人打开"。三个口径不得混用（docs/02 §4）：格点判级日数（十年基线：干旱 轻 69／中 43／重 10 天/年，热害 关注 22／轻 8 天/年）≠ 单园块并发动作条目数（每条提示带 3–4 个动作）≠ 试点中实际被转发的条数。
- ⑤是把干旱分级从"可复算"推进到"可对表"的最小数据来源（评审 C-Q10 指出原设计不采集任何定标所需观测量）：不引入仪器与费用，凭农事常识即可完成；用它对六个物候期做方向一致性核对，并作为开花期解除"蒸散口径封顶中"的依据之一。
- **反事实提示对照（评审 C-Q7）**：同一季记录**农技员自发**发出的提示条数与时点（微信群、简报、广播留痕），与工具输出做**内容差**（工具给了什么他没给）与**时间差**（谁更早）比对。若结果显示动作集合相同、时点差 ≤1 天，则本项目相对"农技员自己发微信群"的净增量只剩"逐园逐日计算 + 留痕可查"，价值主张据此改写，不宣称提供农户看不到的判断。
- 大模型解释层与纯规则问答分组试用，比较追问次数与理解程度；
- 期间若发生真实高温/低温/连阴雨过程，记录提示时间 vs 农户实际防护时间；同时记录 ECMWF 预报命中情况，反哺预报路径回测（预报路径当前零回测）。

### 第 11–13 周：复盘与度量（目标一律写成分子分母，可判失败）

n=1–2 户时百分比没有区分力，故目标列全部改为**可数的分子/分母**，并给出判失败条款：

| 指标 | 定义 | 目标（n=2 户、13 周为例） |
|---|---|---|
| 周活跃 | 每周至少打开 1 次的"户·周"数 | ≥18/26 户·周（约七成） |
| 建议采纳率 | 中/重级提示中被执行的动作数 / 提示动作数 | ≥5/10；**最小分母条款：中重级提示不足 5 次则不出数、只报案例** |
| 越冬准备就绪率 | 11 月准备清单执行项数 /（4 项 × 户数）。清单四项均为本工具自身建议动作，故只测"建议是否被执行"，不宣称测"建议是否有益" | ≥6/8 |
| 提示时效 | 风险等级达标日 vs 农户实际防护日的提前量（逐次记录，两个具体日期） | 每次过程均记录；≥1 天记为达标，90 天内只有一次过程时按案例证据呈现 |
| 满意度 | 期末逐户打分，不用均值制造假精确 | 2/2 户均 ≥4 分；任一户 ≤2 分即判该指标未达标 |
| 续用意愿 | 期末明确愿意继续使用的户数 | 2/2；仅 1/2 判未达标 |
| 提示负担自查 | 每用户每周"轻+"级提示条数与查阅条数之比；提出"少提示"的用户数 | 记录值，不设目标 |
| 末端传达率（粗测） | 节点向末端小农户传达的次数占比；核查形态=带日期群转发截图/张贴照片/期末抽核 2–3 户问"是否从 X 处收到过建议"（失配率对冲虚高） | 记录值，不设目标 |

**判失败条款（事先写死）**：周活跃 <14/26 户·周、或越冬就绪 <3/8、或任一试点户全程未打开过工具——三者任一发生即判"试点未达核心目标"，不得改口径、不得改分母。
**小样本通用报法**：n<10 一律先报分子分母原始数，百分比只作括号补充且必须附 n 与观察周期；单人流失对指标的影响幅度一并写出（n=2 时 1 户=50 个百分点）。
**评估口径分栏**：历史回放场景的评估一律定性为"意向/演练评估"，与真实采纳率分开呈现、不并口径。
**独立核查的取舍（承认弱点）**：满意度与续用意愿由项目人本人微信采集，存在熟人+付费关系的社会期许偏差；采纳率部分对冲=要求动作凭证（涂白照片/农资单据/灌水记录）+ 时效取两个具体日期。**不假装设计了盲评或第三方核查。**

**退场机制（已落成代码开关，不是措辞）**：本项目无自建后端、不落库、无账号，**没有可发公告的用户名单**，因此退场只能走实际可触达的通道，现已实现：
- `index.html` 顶部预留 `#sunset` 横幅、`app.js` 顶部常量 `SUNSET_DATE`（默认留空即不显示）。停服决策时把日期填入 `SUNSET_DATE` 并重新部署，**任何打开页面的人都会看到"还剩 N 天"与归档说明**；`tools/smoke_app.mjs` 已断言"空值不显示、填值显示且带剩余天数"。
- 同时对已建立联系的试点户做书面/群内通知，并在 README 与社区作品帖发布公告。
- **耗尽判定线（写死时点与动作）**：2026-12-31、2027-03-31 两个季度末由项目人自查——若 §8 所列渠道标准的 ①–⑤ 仍未齐备（无任何具名渠道资助或书面挂靠意向），则执行：填入 `SUNSET_DATE` 启动 90 天停服横幅 + README 顶部挂归档声明 + 仓库设为只读归档。不无限期挂着。
- **移交**：发布可 fork 的移交包（物候表模板、坐标与阈值替换说明、确认流程文档）；**不设指定接收方**——若当地农技中心书面同意接收，则连同校准记录一并移交（"移交"需要接收人，此前写法把两件事混成一句，已更正）。
- 成本与单点：最小运维=规则库年度校准 + API 适配（估 3–5 人日/年，无服务器账单）；**bus factor = 1**，全部维护依赖项目人个人可支配时间，目前无第二个人或机构承诺接手。因此本年度定位是"**可自助复算的开源作品 + 移交包**"，不自称"可依赖的公共基础设施"。

## 4. 已完成的第一步验证（历史回测，输入序列已冻结可离线复算）

- 独立 Python 实现（`tools/backtest.py`，四类风险全覆盖）复算 2022 年：热害首个"重"级提示（2022-08-04，39.2℃）比峰值（08-07，40.9℃）**提前 3 天**；全程"重"级 13 天。**归因不抢功**：该提示由单日 ≥39℃ 阈值触发，连续日数升级同过程另贡献 3 天"重"级且最早出现在 08-10（峰值之后）；
- **等价性被脚本强制**：`tools/parity_check.py` 对 4 个真实窗口 442 天逐日比对四类风险与物候判定，另有 33 组阈值边界合成用例（期望值按规则文本单独写死），全部通过；阈值常量（含开花期封顶）由第 3 层与"用冻结序列现算的 p75/p90/p99"绑死；
- **闸门经变异测试自证**：`tools/mutation_test.py` 把修过的每类分叉重新注入临时副本，**15 个变异全部执行且全部被拦下**（含"两侧同步改阈值"这类对拍必然放过、由回归闸门兜住的改动）；
- **干旱双口径与 warm-up 更正**：2022 年区间在带 35 天 warm-up 的正确喂数下为"重"8 天／"中"54 天、首个提示 2022-06-01（此前材料里的"中 3/重 0"是窗口前 29 天被人为致盲的伪影）；蒸散口径在 2022-08-24~27 判"重"（def30 123–138 mm > 膨大期 p99 122.6），同期纯降水口径最高只判"中"（docs/02 §5）；
- **十年基线**（`tools/baseline_stats.py`，2016–2025 共 3653 天）：提示负担各级年日数中位数、休眠期照判则 89.8% 天数带级的常驻率、ET0 口径试验（详见 docs/02 §4–§5）；
- 页面内置 2022 热害 / 2025 秋汛 / 2021 冬寒潮三个回放场景，评审可自助复验（2025 秋汛场景已明示"降水统计与事件回顾，非引擎风险等级"）。

## 5. 证据上限（诚实声明）

- n=1–2 户（或降级 5–10 户）的设计只能回答"会不会用、执不执行"；
- 自报采纳数据存在社会期许偏差，仅部分对冲（见 §3），是本验证设计的真实弱点；
- 花期低温的完整田间验证要等 2027 年 3–4 月（本轮只覆盖采后+越冬）；
- "换物候表即复制"仅对同气候带柑橘产区成立，跨产区/跨作物必须先经当地农技数据校准。

**本轮试点在逻辑上无法证明的结论清单（对外一律不宣称）**：①减损/增收效果；②末端小农户实际受益户数（乘数估计，未核）；③采纳率的统计显著性（分母稀疏）；④**异地复制的真实人日成本——已拆为两栏：④a 文档层能否被陌生人照文档自助走通（可由 §6 的 runbook 实测证明）；④b 对接层人日（协议签订、农技确认回路建立、禁用清单核实）依赖线下关系，runbook 测不到，仍未测**；⑤干旱风险的分级能力（命名承诺最弱环，阈值未与本地旱情对表）；⑥预报技巧（预报路径零回测）；⑦付费意愿（WTP 访谈未做）。

## 6. 迭代计划

- 试点反馈 → 校准阈值与物候表（每两周一次）；
- **ET0/水分亏缺口径**：**已在首发版上线**（def30 按物候期取十年 p75/p90/p99，只抬高等级；开花期因留出检验失准而封顶"中"，定标方法与证据见 docs/02 §5）。试点期的任务不是"决定是否上线"，而是两件事：①用 §3 记录项⑤的手捏墒情与灌水日期，对六个物候期做**方向一致性核对**（工具判"重"的那几周，农户是否确实认为地干/需要灌水）；②完成开花期解除封顶所需的 2027 年春季花期田间对表。**若 2027 花期前本地旱情对表仍未完成，则对外表述降级为"降水亏缺与蒸散需求监测"，副标题去掉"知旱"，README 的"极端旱涝"叙事同步收窄**（评审 C-Q10 要求的可判失败判据，此处接受并写死）；
- **复制性举证动作 runbook（补齐四项空缺）**：编写"陌生产区按清单自建"文档（物候表／坐标替换／禁用投入品清单／确认流程四步），并满足下列判据才计为④a 的证据：
  - **执行人**：一位不在本项目语境中、有农业或数据背景的使用者（社区网友或朋友，试点期内确定，不预先指定人）；
  - **谁付**：默认不计报酬、以成果署名换取；若对方要求付费，从 §2 的 3200 元上限内列支，不另找资金；
  - **截止**：2027-03-31 前完成一次；
  - **pass/fail 判据（可判失败）**：①全程未向项目人提问即完成四步（每提问一次记一项 fail）；②产出可本地运行的站点并完成坐标与物候表替换；③如实记录卡点与实际耗时。三项缺一即只报"文档部分可读"，不报"可复制"。
- 高频追问问题沉淀为规则库条目，减少对 LLM 的依赖；
- 试点成功后向周边乡镇扩展；同一引擎支持茶叶等相邻作物须重建物候表、库周禁用投入品清单与农技确认回路（跨作物＝强校准，估 5–15 人日/产区，见 docs/01 §6）——"库区特色作物气候服务"是**远期**路径，12 个月内不启动。

## 7. 风险与兜底

- 合作社招募不及时 → 降级为 5–10 户种植大户 + 农技员访谈式试用（按 §3 小样本报法）；
- 现场无法成行 → 按 §2 砍序第①项执行（减为一次现场），回访降为每两周一次；**不同时**引入"委托当地对接人全程代办"的高成本方案（那会把差旅省下的钱换成 13 周人力补偿，更贵）——如需委托，只委托期末一次的现场复盘；
- 90 天内无极端过程 → 用历史回放 + 秋冬季寒潮过程补充评估，回放评估定性为"意向/演练评估"；
- 确认资源不可得或付款合规核不出 → 外部性类动作一律不推送，产品形态按 §8"工作台形态（备选）"收窄；
- 隐私与合规 → 仅坐标与评分，凭证按 §2 规则处理，可随时退出（退出即删原始凭证）。

## 8. 市场与可持续性（配合评审维度）

**12 个月结论（一句话，不绕）**：**本项目 12 个月内收入为 0**，且已选定的赛道不追求收入。理由：数千节点 × 数百元年费的理论天花板仅数十万元/年、养不起全职团队；且按 §2 的日历，收入线前置条件③（至少一个完整风险季的价值证据）最早 2027 年春季末才可能齐备——**这是结构性为 0，不是"暂未验证"**。

**定位统一口径**：本年度为"**可自助复算的开源作品 + 移交包 + 项目制**"，不使用"公共基础设施"自我描述（bus factor=1 撑不起那个词），也不做商业生意叙事。

**资金渠道的举证标准（接受评审给出的尺子，逐条对齐）**：一条渠道要算"已核"，必须齐 ①发布单位全称与指南/文件名；②下一批申报窗口的起止日期；③申报主体资格的**原文条款**（个人可否、挂靠路径）；④其验收指标与本项目可提供数据的逐项对照；⑤挂靠方或资助方的**书面意向**（邮件或会议纪要）。**①–④不齐就写"暂无渠道"，不许写类别名。** 按此标准，当前所有渠道 ①–⑤ 均缺 → **结论：暂无已核验渠道**；此前材料里"水源区生态补偿/面源治理类政府专项"的写法已删除（该类专项与生态补偿的验收通常落在环境结果指标上，本项目不采集农资投入量、施肥与退水数据，装不进其验收项，属错配）；后续若核出气候适应/数字乡村/农业科技服务类中确有不落环境结果指标的渠道，按 ①–⑤ 补齐后再写进材料。

**"窗口内第一笔钱"的口径矛盾（已消除）**：此前一处写"个人劳务型单次服务可在窗口内收费"，另一处写"四项服务起算时点在主体设立之后"。现定为：**12 个月内不安排任何收入**，包括单次劳务收费。理由是收费会使数据链路落入 Open-Meteo 免费层的商业使用范围（需付费订阅 Key，费用未核），且个人无票、无责任承接能力，一次报价带来的争议成本高于收益。若主体与数据许可两件事在 2027 年后落实，再按"待验证定价区间"重新评估年费。

**开源与收费的分界（精确到功能名，可证伪）**：永久免费＝页面现有全部功能——风险看板与四类等级、97 天风险日历、三个回放场景、建议报告导出、CSV 导出、内置规则问答、自定坐标园块、源码与规则库本身（可自部署）。**不存在"付费才解锁的软件功能"**。远期若真要收费，只绑定人工服务四项：本地物候校准、库周禁用清单维护、风险周报代运营、故障响应与责任对接；其中"故障响应与责任对接"在无主体阶段无法交付，故该清单在 12 个月内不启用。为避免自废 WTP 证据：这四项服务**不在试点期免费提供**，试点期免费的只有工具本身与农技员的周报代生成（且属 §3 的激励，须在协议第⑥条下声明不构成延续承诺）。

**工作台形态（备选，非默认）**：若 §3 的确认资源或付款合规不成立，产品形态收窄为"给乡镇农技员用的工作台"——用户＝农技员（一人覆盖数千亩），免费边界不变（工具全免费），价值主张从"替农户决策"改为"替农技员逐园逐日算 + 留痕"。诚实标注两点：①该形态下付费方只能是农技服务中心或合作社购买运维，而"购买运维"即需签约主体资格，因此**窗口内该形态同样收入为 0**；②赛事"气候适应与韧性"叙事的服务末端仍是果农（农技员是其转译层），但材料会明写形态收窄，不会继续把它讲成面向农户的 C 端产品。

**远期观察项（12 个月收入贡献 = 0，依赖主体与资质）**：气象数据授权运营场景分成；"气象+保险"联动。挂靠已授权主体或被农技体系采纳后方可启动。数据源成本约束见 docs/02 §1（免费层限非商业用途，收费即需付费订阅，成本须计入任何定价）。

**影响力口径**：可测量的是"数百个专业节点直接服务"；末端受益农户数为乘数估计（数百至数千户），试点粗测传达率与末端执行占比，未核前不作受益宣称。"10 万果农"仅为产业背景口径（湖北日报 2024-10）。公益底线的可证伪形式＝上面的"免费＝现有全部功能 + 无付费墙 + 可自部署"清单，以及小农户经节点间接获得建议的路径（导出报告可打印/张贴）。

**12 个月内明确不做**：跨产区复制、APP 开发、需资质的数据授权运营、任何需要主体资格的签约与收费（含单次劳务）、"公共基础设施"式承诺。

**退出触发清单（可证伪，任一发生即启动停更与撤销背书流程，而不是无限期挂着）**：①2027-03-31 前 §8 的渠道标准 ①–⑤ 仍不齐备；②试点连续 6 周零活跃（无任何一户打开）；③确认回路整季零响应；④项目人连续 8 周无法投入 ≥4 小时/月（可支配时间断供）；⑤最终没有任何单位签字——此时按"基层不愿为未验证工具背书"记录为需求侧证据，并据此收窄价值主张。执行动作（按顺序）：填入 `SUNSET_DATE` 启动 90 天停服横幅 → README 与社区帖挂归档声明 → 向已签署方发出撤销背书与数据删除通知 → 仓库设为只读归档。检查时点为每季度末（2026-12-31、2027-03-31），执行人为项目人本人。

**赛后 18 个月若时间或资金耗尽，试点户手上还剩什么（评审 C-Q9①）**：不是"服务"，而是三样可自助的东西——①已导出的建议报告 HTML 与 97 天风险日历 CSV（打印可张贴，不依赖本站在线）；②开源规则库与物候表（任何人可自部署）；③移交包文件（物候表模板、坐标与阈值替换说明、确认流程文档）。这三样不随本站停服失效，也是本项目唯一敢承诺的留存形态。

**末端告知的最低形式（评审 C-Q8）**：工具不经末端小农户同意也无法触达他们，因此只做两件事并在材料里写明：①导出报告页眉固定一句"本建议由开源工具生成、未经本地核验；转述给其他农户时请一并说明这一点"；②张贴/转发模板沿用同一句。不做"已获末端知情同意"的表述——抽核 2–3 户只记录编号与答案、不记姓名，且须经合作社许可并作口头知情说明后才会进行，属**验证性访谈而非数据采集**。
