# 03 · 验证计划（90 天真实场景试点）

## 1. 验证目标

回答四个问题：真实用户会不会用？建议有没有被执行？执行后有没有减少损失/降低成本？方案能不能复制到下一个产区？

## 2. 目标用户与招募

- **对象**：丹江口库区 1–2 家柑橘合作社（或种植大户 + 乡镇农技员），覆盖 30–100 亩果园；
- **招募方式**：通过库区乡镇农技服务中心、合作社对接；已准备口头/文字版需求访谈提纲；
- **伦理**：免费试用；不采集个人身份信息；使用数据仅含园块坐标与反馈评分。

## 3. 验证设计（90 天，三段）

### 第 1–2 周：基线与校准
- 访谈记录：当前如何决策灌溉/防冻/花期管理（原话留存）；
- 用试点园块坐标替换默认坐标；按当地品种微调物候表起止日期；
- 确定对照方式：试点户决策记录 vs 邻近未使用户的常规决策（注："邻近未使用户"存在自选择偏差——愿意采用新工具者管理水平本可能更高，故对照仅作参考，不做因果宣称）；
- **农技员确认回路**：试点期全部建议动作（尤其化学品类：磷酸二氢钾、保水剂等）先经农技员确认适用性后才推送给农户；规则库增设"库周限用/禁用投入品"核对项（水源区约束，本项目规则库当前盲区，已列入试点任务）。

### 第 3–10 周：真实使用（覆盖一个完整风险过程）
- 每周回访一次（微信），记录：
  1. **提示接收**：本周收到哪些中/重级提示；
  2. **动作采纳**：按建议执行了哪些动作（浇灌/覆盖/熏烟/涂白等），未执行的原因；
  3. **主观评价**：1–5 分满意度 + 是否愿意继续用 + 是否愿意推荐给其他农户；
- 大模型解释层（DeepSeek）与纯规则问答分组试用，比较追问次数与理解程度；
- 期间若发生真实高温/低温/连阴雨过程，记录提示时间 vs 农户实际防护时间；同时记录 ECMWF 预报命中情况，反哺预报路径回测（首发版预报路径零回测，见数据与AI说明）。

### 第 11–13 周：复盘与度量
核心指标（目标值）：

| 指标 | 定义 | 目标 |
|---|---|---|
| 周活跃使用率 | 每周至少打开 1 次的用户占比 | ≥70% |
| 建议采纳率 | 中/重级提示中被执行动作的比例（**最小分母条款：试点期中/重级提示不足 5 次则不出数，只报案例**） | ≥50% |
| 越冬准备就绪率 | 11 月准备清单（涂白/培土/覆盖物资/灌水设施检查）执行占比——越冬季主指标，分母是清单项而非灾害次数（低频灾害下采纳率会稀疏空转） | ≥60% |
| 提示时效 | 风险等级达标日 vs 农户实际防护日的提前量（若 90 天仅一次过程，为案例证据非统计结论） | ≥1 天 |
| 满意度 | 期末 1–5 分 | ≥3.8 |
| 续用意愿 | 期末明确愿意继续使用的比例 | ≥80% |
| 末端传达率（粗测） | 节点用户向末端小农户传达建议的次数占比；**核查形态**=群转发截图带日期/张贴照片/期末抽核 2–3 户末端农户问"是否从 X 处收到过建议"（失配率对冲虚高） | 记录值，不设目标 |

**评估口径分栏**：历史回放场景的评估一律定性为"意向/演练评估"，与真实采纳率分开呈现、不并口径。

**农技员确认回路的激励与降级设计**：①激励=试点期列支顾问费/误工补偿 + 系统代工周报替其省工 + 试点成果署名归其单位，长期争取纳入基层农技服务采购，不做义务劳动；②分级确认：化学品类 fail-closed（不确认不推，宁缺毋滥）、非化学品类超时自动放行但带"未经农技员确认"标注、常规动作季度批量预确认（审规则库而非逐条建议）；③责任分流：确认的是适用性（禁用清单/适期），等级正确性仍归系统，三段留痕。

**退场机制（公益项目的义务包括不弃坑）**：停服前 90 天公告；代码与规则库开源存档；物候表与校准流程移交当地农技中心。最小运维模型=规则库年度校准 + API 适配（估 3–5 人日/年，无服务器账单，主体待定——团队/合作社/挂靠农技中心）。核心交付之一是"可直接提交水源区生态补偿/面源治理专项的证据包"（申报渠道调研列入决赛后任务清单）。

## 4. 已完成的第一步验证（历史回测）

- 用独立 Python 实现（`tools/backtest.py`）复算 2022 年热害：首个"重"级提示（2022-08-04）比温度峰值（08-07，40.9℃）**提前 3 天**；全程"重"级 13 天，提示窗口完整覆盖；
- 页面内置 2022 热害 / 2025 秋汛 / 2021 冬寒潮三个回放场景，评审可自助复验。

## 5. 证据上限（诚实声明）

- n=1–2 户的设计只能回答"会不会用、执不执行"，回答不了"减损多少"（后者需跨年多事件，90 天不支撑，不列入目标）；
- 自报采纳数据存在社会期许偏差，未设计独立核查（照片/农资记录），是本验证设计的真实弱点；时效指标要求"提示日期 vs 防护日期"两个具体日期以部分对冲；
- 花期低温的完整田间验证要等 2027 年 3–4 月（本轮试点窗口只覆盖采后+越冬），其余风险以回测背书；
- "换物候表即复制"仅对同气候带柑橘产区成立，跨产区/跨作物必须先经当地农技数据校准。

## 6. 迭代计划

- 试点反馈 → 校准阈值与物候表（每两周一次）；
- 高频追问问题沉淀为规则库条目，减少对 LLM 的依赖；
- 试点成功后向周边乡镇扩展；同一引擎更换物候表即可支持茶叶（相邻产业）——构成向"库区特色作物气候服务"复制的路径。

## 7. 风险与兜底

- 合作社招募不及时 → 降级为 5–10 户种植大户 + 农技员访谈式试用；
- 90 天内无极端过程 → 用历史回放 + 预报过程（秋冬季寒潮概率高）补充评估；
- 隐私与合规 → 仅坐标与评分，明示用途，可随时退出。

## 8. 市场与可持续性（配合评审维度）

**12 个月定位（诚实选边）**：本年度按"低成本公益基础设施 + 项目制"举证，不做生意叙事——数千节点 × 数百元年费的理论天花板仅数十万元/年、养不起全职团队；可持续机制靠赛事奖金、水源区生态补偿/面源治理类政府专项与基金会项目续命，当前均未申请。

**唯一 12 个月内可能的收入线**：合作社/农技服务中心年费（"卖服务不卖软件"：本地物候校准、库周禁用清单维护、风险周报代运营、故障响应）。启动前置条件：①主体与发票能力；②WTP（支付意愿）访谈完成；③至少一个完整风险季的价值证据。三者齐备前收入为 0，材料不再把"数百元"表述为测算价而是**待验证定价区间**。

**远期观察项（12 个月收入贡献 = 0，依赖主体与资质，不作为收入来源宣称）**：气象数据授权运营场景分成；"气象+保险"联动。挂靠已授权主体或被农技体系采纳后方可启动。

**影响力口径**：可测量的是"数百个专业节点直接服务"；末端受益农户数为乘数估计（数百至数千户），试点将粗测"建议传达率/末端执行户占比"，未测前不作受益宣称。"10 万果农"仅为产业背景口径（湖北日报 2024-10）。
