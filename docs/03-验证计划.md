# 03 · 验证计划（90 天真实场景试点）

## 1. 验证目标

回答四个问题：真实用户会不会用？建议有没有被执行？执行后有没有减少损失/降低成本？方案能不能复制到下一个产区？

**能力边界先说清**：本轮 90 天能回答前两问；第三问只能回答"有没有出现可记录的执行动作"，回答不了"减损多少"（需跨年多事件）；第四问**本轮不做验证**（12 个月内只做丹江口一地，复制性证据等级=0，见 §5、§8）。

## 2. 目标用户与招募

- **对象**：丹江口库区 1–2 家柑橘合作社（或种植大户 + 乡镇农技员），覆盖 30–100 亩果园；
- **招募方式**：通过库区乡镇农技服务中心、合作社对接；已准备口头/文字版需求访谈提纲；
- **线下执行（本项目最大的单点风险，直说）**：团队常驻杭州，试点需要乡镇对接、基线访谈与回访。安排为**自费现场两次**（第 1–2 周启动与基线访谈、第 11–13 周期末复盘），中间 8 周以微信回访维持；若现场成行受阻，整体按 §7 降级为"5–10 户种植大户 + 农技员访谈式试用"，并按 §3 的小样本口径报数，不用百分比掩盖样本量；
- **试点前置协议（未签则不启动）**：与合作社/农技中心各签一页纸《试用与责任约定》，内容至少含：①工具仅为农事辅助、不构成灾害预警；②错误提示的责任上限与免责范围；③数据用途、留存期限与撤回方式；④署名与成果发布须经书面同意；⑤试点失败或退出时，撤销背书的表述口径。在此之前，材料不声称已获任何单位同意；
- **伦理与证据留存**：不采集个人身份信息（姓名、手机号、门牌）；使用数据仅含园块坐标与反馈评分。试点中产生的凭证（群转发截图、张贴照片、抽核问答）按以下规则处理：入库前对群名/昵称/头像打码；抽核问答只记录编号与答案，不记姓名；原始凭证仅本地留存、不随仓库开源，对外证据包只使用**聚合统计**且经书面同意；用户退出即删除其原始凭证，仅保留匿名聚合值；
- **试点期大模型层的 Key 与用量**：由项目方统一提供 Key 并承担用量（上限 100 元内，超量即停用该分组）；无 Key 或未愿参与者走内置规则问答。分组对比只比较"追问次数与理解程度"，不比较等级正确性（等级两侧同源）。

## 3. 验证设计（90 天，三段）

### 第 1–2 周：基线与校准
- 访谈记录：当前如何决策灌溉/防冻/花期管理（原话留存）；
- 用试点园块坐标替换默认坐标；按当地品种微调物候表起止日期；
- 确定对照方式：试点户决策记录 vs 邻近未使用户的常规决策（注："邻近未使用户"存在自选择偏差——愿意采用新工具者管理水平本可能更高，故对照仅作参考，不做因果宣称）；
- **投入品与生态外部性确认回路**（水源区特化）：核对范围不再按"化学/非化学"二分，而按**是否有环境外部性**分级——①需先确认后才推送（fail-closed）：化学品类（磷酸二氢钾、保水剂、防冻保护剂）、农事熏烟与明火、地膜/防寒布等覆盖材料（残膜与废弃物）、大水漫灌类灌溉动作；②可自动推送但标注"未经农技员确认"：覆盖秸秆、涂白、培土、遮阳、修剪等非外部性动作；③常规动作按季度批量预确认（审规则库而非逐条建议）。规则库增设"库周限用/禁用投入品与禁烧/覆膜规定"核对项（当前为盲区，已列入试点任务）；
- **农技员确认回路的激励（含钱的来源）**：试点期顾问费/误工补偿按当地零工日薪估 **100–150 元/人日 × 6–8 人日 = 600–1200 元**，在当前无任何外部资金的情况下**由项目人自费列支**（这是真实预算，不是画在表上的项目经费）；另有两项非现金激励：系统代生成风险周报替其省工、试点成果署名归其单位。基层农技推广体系的年度考核中没有"配合外部工具逐条确认"这一项，因此**不假设义务劳动可持续**；若确认资源仍不可得，产品形态按 §8 收窄为"给农技员用的工作台"。

### 第 3–10 周：真实使用（覆盖一个完整风险过程）
- 每周回访一次（微信），记录：
  1. **提示接收**：本周收到哪些中/重级提示；
  2. **动作采纳**：按建议执行了哪些动作（浇灌/覆盖/熏烟/涂白等），未执行的原因；
  3. **主观评价**：1–5 分满意度 + 是否愿意继续用 + 是否愿意推荐给其他农户；
  4. **提示负担**：本周共收到多少条"轻"级及以上提示、实际查看几条、有无主动要求"少提示"（与十年基线对照：正常年景"关注"级约 22 天/年、"轻"级热害约 8 天/年、"轻"级干旱约 50 天/年，见 docs/02 §4）；
- 大模型解释层（DeepSeek）与纯规则问答分组试用，比较追问次数与理解程度；
- 期间若发生真实高温/低温/连阴雨过程，记录提示时间 vs 农户实际防护时间；同时记录 ECMWF 预报命中情况，反哺预报路径回测（首发版预报路径零回测，见 docs/02）。

### 第 11–13 周：复盘与度量
核心指标（目标值）：

| 指标 | 定义 | 目标 |
|---|---|---|
| 周活跃使用率 | 每周至少打开 1 次的用户占比 | ≥70% |
| 建议采纳率 | 中/重级提示中被执行动作的比例（**最小分母条款：试点期中/重级提示不足 5 次则不出数，只报案例**） | ≥50% |
| 越冬准备就绪率 | 11 月准备清单（涂白/培土/覆盖物资/灌水设施检查）执行占比——越冬季主指标，分母是清单项而非灾害次数（低频灾害下采纳率会稀疏空转）。**清单来源披露**：四项均为本工具自身建议动作，故该指标测的是"建议是否被执行"，不宣称测"建议是否有益" | ≥60% |
| 提示时效 | 风险等级达标日 vs 农户实际防护日的提前量（若 90 天仅一次过程，为案例证据非统计结论） | ≥1 天 |
| 满意度 | 期末 1–5 分 | ≥3.8 |
| 续用意愿 | 期末明确愿意继续使用的比例 | ≥80% |
| 提示负担自查 | 每用户每周"轻+"级提示条数与查阅条数之比；提出"少提示"的用户数 | 记录值，不设目标 |
| 末端传达率（粗测） | 节点用户向末端小农户传达建议的次数占比；**核查形态**=群转发截图带日期/张贴照片/期末抽核 2–3 户末端农户问"是否从 X 处收到过建议"（失配率对冲虚高） | 记录值，不设目标 |

**小样本报法（防止降级方案让数字自动变漂亮）**：n<10 时一律**只报分子分母原始数**（如"3/5 户执行"），不报百分比；所有百分比须同时给出 n 与观察周期；单一用户流失对指标的影响幅度一并写出。
**评估口径分栏**：历史回放场景的评估一律定性为"意向/演练评估"，与真实采纳率分开呈现、不并口径。
**独立核查的取舍（承认弱点）**：满意度与续用意愿由项目人本人微信采集，存在熟人+付费关系的社会期许偏差；采纳率部分对冲=要求动作凭证（涂白照片/农资单据/灌水记录）+ 时效指标取两个具体日期。**不假装设计了盲评或第三方核查。**

**农技员确认回路的降级设计**：①分级确认（见 §3 第 1–2 周）；②责任分流而非转嫁：农技员确认的是"适用性"（限用清单、农时是否合适），等级正确性仍归系统，三段留痕（系统输出→确认记录→农户执行记录）；③超时与不回复：外部性类不推送（宁缺毋滥），非外部性类超时放行并标注。

**退场机制（公益项目的义务包括不弃坑）**：**先承认触达能力的边界**——本项目无自建后端、不落库、无账号，除试点户（微信联系）外无法主动触达任何匿名访问者，因此"停服前 90 天公告"只能以两种形式兑现：①试点户书面/群内通知；②页面顶部挂停服倒计时横幅（对已打开页面的访问者可见）+ 仓库 README 与社区作品帖公告。不声称能做"用户名单群发"。其余：代码与规则库开源存档；物候表与校准流程移交当地农技中心。最小运维模型=规则库年度校准 + API 适配（估 3–5 人日/年，无服务器账单）；**bus factor = 1**：全部维护依赖项目人个人可支配时间，目前无第二个人或机构承诺接手，故本年度定位是"可自助复算的开源作品 + 移交包"，不自称"可依赖的公共基础设施"。

## 4. 已完成的第一步验证（历史回测，输入序列已冻结可离线复算）

- 独立 Python 实现（`tools/backtest.py`）复算 2022 年热害与干旱：热害首个"重"级提示（2022-08-04，39.2℃）比温度峰值（08-07，40.9℃）**提前 3 天**；全程"重"级 13 天。**时效归因不抢功**：首个"重"级由单日 ≥39℃ 阈值触发，连续日数升级在同过程另贡献 3 天"重"级（最早 08-10，已在峰值之后）；
- **两套实现等价性已被脚本强制**：`tools/parity_check.py` 对 4 个真实窗口 442 天逐日比对四类风险与物候判定，另有 23 组阈值边界合成用例（rain30 的 15/30/45mm、连旱 8/15/25 天、连续高温 3/5 天、单日 33/35/37/39℃、跨物候边界跳档、断链清零、窗口不满 30 天、闰日），全部通过；
- **十年提示负担基线**（`tools/baseline_stats.py`，2016–2025 共 3653 天）与 ET0 水分亏缺口径的可行性试验（含否定"直接 OR 并入"的量化理由）见 docs/02 §4–§5；
- 页面内置 2022 热害 / 2025 秋汛 / 2021 冬寒潮三个回放场景，评审可自助复验。

## 5. 证据上限（诚实声明）

- n=1–2 户（或降级 5–10 户）的设计只能回答"会不会用、执不执行"；
- 自报采纳数据存在社会期许偏差，未设计独立核查（照片/农资记录部分对冲），是本验证设计的真实弱点；
- 花期低温的完整田间验证要等 2027 年 3–4 月（本轮试点窗口只覆盖采后+越冬），其余风险以回测与基线背书；
- "换物候表即复制"仅对同气候带柑橘产区成立，跨产区/跨作物必须先经当地农技数据校准。

**本轮试点在逻辑上无法证明的结论清单（对外一律不宣称）**：①减损/增收效果（需跨年多事件与对照）；②末端小农户实际受益户数（乘数估计，未核）；③采纳率的统计显著性（分母稀疏）；④异地复制的真实人日成本（从未做过一次陌生产区复制）；⑤干旱风险的分级能力（命名承诺的最弱环，阈值未经本地旱情对表）；⑥预报技巧（预报路径零回测）；⑦付费意愿（WTP 访谈未做）。

## 6. 迭代计划

- 试点反馈 → 校准阈值与物候表（每两周一次）；
- **ET0/水分亏缺口径定标**：按物候期分别取距平分位阈值（候选：休眠 p90≈40mm、开花 p90≈86mm、膨大 p90≈87mm），与合作社地块的田间水分观测/农户响应联校后决定是否上线（首发版不上，理由与量化试验见 docs/02 §5）；
- **复制性从推定变证据的最低动作**：编写"陌生产区按清单自建"的 runbook（物候表/坐标/禁用清单/确认流程四步），请一位不在本项目语境中的使用者照文档独立走通，实测其耗几人日、卡在哪一步，结果如实写入材料；12 个月内仍不做实际跨产区部署；
- 高频追问问题沉淀为规则库条目，减少对 LLM 的依赖；
- 试点成功后向周边乡镇扩展；同一引擎支持茶叶等相邻作物须重建物候表、库周禁用投入品清单与农技确认回路（跨作物＝强校准，估 5–15 人日/产区，见 docs/01 §6）——构成"库区特色作物气候服务"的**远期**复制路径，12 个月内不启动。

## 7. 风险与兜底

- 合作社招募不及时 → 降级为 5–10 户种植大户 + 农技员访谈式试用（指标按 §3 小样本报法，只报分子分母）；
- 现场无法成行 → 委托 1 名当地对接人（农技员或合作社管理员）执行招募与回访，按 §3 列支误工补偿，并把回访频率降为每两周一次 + 期末一次现场；
- 90 天内无极端过程 → 用历史回放 + 预报过程（秋冬季寒潮概率高）补充评估，回放评估定性为"意向/演练评估"；
- 农技员确认资源不可得 → 外部性类动作一律不推送（宁缺毋滥），产品形态收窄为"农技员工作台"，付费对象相应改为农技服务中心购买运维；
- 隐私与合规 → 仅坐标与评分，凭证按 §2 的打码与留存规则处理，明示用途，可随时退出（退出即删原始凭证）。

## 8. 市场与可持续性（配合评审维度）

**12 个月结论（一句话，不绕）**：**本项目 12 个月内收入为 0**，且已选定的赛道不追求收入——按"低成本公益基础设施 + 开源作品 + 项目制"举证。理由：数千节点 × 数百元年费的理论天花板仅数十万元/年、养不起全职团队；可持续机制靠赛事奖金、水源区生态补偿/面源治理类政府专项与基金会项目续命，**当前均未申请，且个人身份通常不具备申报主体资格**（政府购买服务与专项资金一般要求法人单位或供应商资质——该项资格限制的具体条款待逐字核验，核验结果与可行的挂靠路径（社团/合作社/农技中心代为申报）一并回填，未回填前不把它写成机制）。

**面源治理类专项的证据错配（自认）**：该类专项验收的是化肥农药减量、退水与面源负荷指标，而本项目不采集农资投入量与施肥数据，现有"证据包"装不进其验收指标。因此本项目更可能的对口渠道是**气候适应/数字乡村/农业科技服务类**项目与志愿服务型资源，而非面源治理专项；渠道清单与匹配度在决赛后按月更新，未落实前写"未申请"。

**唯一在 12 个月内可能出现的收入线**（前置条件齐备前收入为 0）：合作社/农技服务中心年费（"卖服务不卖软件"）。启动前置条件：①主体与发票能力；②WTP（支付意愿）访谈完成；③至少一个完整风险季的价值证据。按当前日历，条件③最早在 2027 年春季末才可能齐备，**故该收入线在 12 个月窗口内实质为 0，不是"暂未验证"而是"结构性为 0"**；材料按此结论表述。若要在窗口内出现第一笔真实付费，唯一不依赖①②③的形态是**个人劳务型单次服务**（一次本地物候校准 + 清单核对，按次收费、不开票、不称"年费"），是否要做由试点期实际询价决定。

**开源与收费的分界（精确到功能名，可证伪）**：永久免费=页面现有全部功能：风险看板与四类等级、97 天风险日历、2022/2025/2021 三个回放场景、建议报告导出、CSV 导出、内置规则问答、自定坐标园块、源码与规则库本身（任何人可自部署）。付费只绑定人工服务四项：本地物候校准、库周禁用投入品清单维护、风险周报代运营、故障响应与责任对接。**不存在"付费才解锁的软件功能"**；同时诚实承认：无主体阶段"故障响应与责任对接"无法交付，故四项服务实际起算时点在主体设立之后。

**远期观察项（12 个月收入贡献 = 0，依赖主体与资质，不作为收入来源宣称）**：气象数据授权运营场景分成；"气象+保险"联动。挂靠已授权主体或被农技体系采纳后方可启动。另需注意：数据源免费层条款限定**非商业用途**（每日 10,000 次上限），一旦收费即构成商业使用，须换付费 Key 或换数据源——该成本必须计入服务定价，不能继续按"边际成本≈0"报（见 docs/02 §1）。
